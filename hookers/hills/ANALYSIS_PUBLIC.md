# Hills 跨平台网络复验与冷启动竞态消除技术报告（开源分享版）

## 1. 概述
- **目标类型**：Flutter 客户端 (混淆 AOT + Rust 网络栈)
- **分析版本**：v1.9.0
- **核心难点**：Dart 快照堆内存动态反序列化、本地假服务器重定向、网络层时序赛跑

---

## 2. 为什么存在“启动两次才生效”的竞态漏洞
在依赖运行时内存字符串重定向（Memory String Rewrite）与本地服务劫持的方案中，常见的竞态时序如下：
1. **反序列化时差**：常量字符串保存在只读快照数据段中，随着 Isolate 启动动态解包进匿名内存映射堆。
2. **全局宽泛扫描的性能瓶颈**：若在几百兆的堆内存中遍历所有通用前缀（如 `https://`），单次扫描耗时过长，容易超过预设门控超时。
3. **假数据穿透真实网络**：一旦门控超时并放行假凭据，客户端网络线程以毫秒级速度直连官方服务器校验，官方返回非法拒绝，导致客户端将“未开通”状态持久化到本地。
4. **二次启动碰巧成功**：第二次启动时因已有系统缓存加速，重定向碰巧在发包前完成，从而表现为“必须启动两次”。

---

## 3. 竞态消除的核心对策
1. **定向高特异性检索**：抛弃宽泛的前缀扫描，使用具体域名或特定路径（如 `api.example.com/functions/v1`）作为特征码，将内存扫描周期压缩至毫秒级。
2. **默认 SKU 预热置位**：预置已知的核心产品标识，消除异步商品目录查询前的广播死锁。
3. **严格门控拦截**：重定向未完成前严禁向引擎交付合成数据，阻断假凭据穿透至真实后端。

---

## 4. 本地凭据持久化与无网自愈
1. **本地响应缓存**：将合成且验签合法的有效返回载荷落地持久化至本地私有文件目录。
2. **离线零等待应答**：冷启动或处于无网络状态时，本地代理服务优先命中磁盘持久化缓存，立即完成闭环授权判定，免去重复动态签发。
